이 사이트는 다이어리 속지처럼 생긴 화면을 쓰고 있습니다. 여기에 테이프가 붙고 날짜 도장이 찍히는 움직임을 더했습니다. 이 글에서는 어떤 효과를 넣었는지, 만들면서 무엇을 조심해야 했는지를 적어 둡니다.

## 무엇을, 왜 움직였나

기준은 하나였습니다. 움직임은 다이어리를 펼치는 손길처럼 보여야 하고, 장식을 위한 장식은 넣지 않는다는 것입니다. 그래서 종이 문구에서 실제로 일어날 법한 동작만 골랐습니다.

- 페이지가 열리면 내용이 14px 아래에서 살며시 올라옵니다.
- 마스킹테이프는 왼쪽부터 쭉 붙습니다.
- 날짜 도장은 크게 나타났다가 살짝 눌리며 자리를 잡습니다.
- 홈 인사말의 형광펜은 글자가 보인 뒤에 그어집니다.
- 목록 줄과 포스트잇은 스크롤을 내리면 하나씩 올라옵니다.

![모션 줄이기 설정 존중, 속지는 움직이지 않기, 미지원 브라우저에서는 그냥 보이기라는 세 가지 원칙](/images/posts/planner-style-motion-with-css/motion-three-rules.png "움직임을 넣을 때 지킨 세 가지")

별도의 애니메이션 라이브러리 코드를 붙이지 않고 CSS의 `@keyframes`와 `transition`으로 처리했습니다. 상단 메뉴가 살짝 들리거나 테마 버튼의 해가 도는 것 같은 마우스 반응도 같은 방식입니다.

## 시작 시각을 어긋나게 놓기

모든 효과가 동시에 시작하면 어디를 봐야 할지 알기 어렵습니다. 그래서 지연 시간을 조금씩 다르게 두었습니다. 속지가 내려앉기 시작하고, 0.12초 뒤에 테이프, 0.25초 뒤에 도장, 0.5초 뒤에 형광펜이 움직입니다.

![속지, 테이프, 도장, 형광펜 효과가 0초, 0.12초, 0.25초, 0.5초에 차례로 시작하는 시간표](/images/posts/planner-style-motion-with-css/motion-entrance-timeline.png "효과마다 다른 시작 시각")

지연이 있을 때는 `animation-fill-mode`의 `backwards` 값이 필요합니다.

```css
.stamp {
  animation: stamp-in 0.5s 0.25s
    cubic-bezier(0.34, 1.56, 0.64, 1) backwards;
}
```

이 값이 없으면 도장이 원래 모습으로 먼저 보였다가, 0.25초 뒤에 갑자기 사라지며 다시 찍힙니다. `backwards`는 기다리는 동안에도 첫 장면을 유지해 줍니다. 애니메이션이 끝난 뒤에는 요소가 원래 스타일로 돌아가므로, 마우스를 올렸을 때 도장이 조금 더 기우는 효과도 그대로 동작합니다.

## 속지는 움직이지 않기

가장 조심한 부분은 속지였습니다. 속지는 `::before` 가상 요소로 뒷장 한 장을 비스듬히 깔고, `z-index: -1`로 뒤에 보냅니다.

그런데 속지 자체에 `transform`이나 1보다 작은 `opacity`가 걸리면 새로운 쌓임 맥락(stacking context)이 생깁니다. 그러면 뒷장의 `-1`은 그 맥락 안에서만 계산되어, 속지의 배경보다 위에 그려집니다. 뒤에 있어야 할 종이가 앞장 위로 비치는 것입니다.

![속지에 transform을 걸지 않으면 뒷장이 뒤에 남고, 걸면 뒷장이 앞장의 글을 덮는 비교](/images/posts/planner-style-motion-with-css/motion-sheet-stacking.png "속지에는 애니메이션을 걸지 않기")

그래서 속지(`.sheet`)에는 애니메이션을 걸지 않고, 페이지 전체를 감싸는 바깥 상자를 움직였습니다. Next.js의 `app/template.tsx`에 `page-enter` 클래스를 단 `div` 하나를 둔 것이 전부입니다.

여기에는 주의할 점이 있습니다. template은 페이지를 옮길 때 새로 그려지지만, 항상 그런 것은 아닙니다. Next.js 문서에 따르면 루트 template은 첫 번째 경로 구간이 바뀔 때 다시 마운트되고, 그보다 깊은 곳에서만 이동하면 그대로 남습니다. `/posts`에서 `/games`로 갈 때는 등장 효과가 다시 걸리지만, 글에서 다른 글로 갈 때는 걸리지 않는 구조입니다.

![경로의 첫 구간이 바뀌면 루트 template이 다시 그려지고, 같으면 그대로 남는 두 가지 예](/images/posts/planner-style-motion-with-css/motion-template-remount.png "이동한다고 늘 다시 그려지지는 않음")

## 움직임이 불편한 사람과 지원하지 않는 브라우저

화면의 움직임에 어지러움을 느끼는 분들은 운영체제에서 모션 줄이기를 켤 수 있습니다. 새로 넣은 등장 효과는 `@media (prefers-reduced-motion: no-preference)` 안에만 적었습니다. 효과를 먼저 걸고 나중에 끄는 대신, 괜찮다고 한 환경에서만 켜는 방식입니다. 메뉴, 버튼, 포스트잇 같은 마우스 반응은 `reduce` 조건에서 전환을 꺼 두었습니다.

스크롤 등장 효과는 `animation-timeline: view()`를 썼습니다. 요소가 화면에 들어오는 정도에 맞춰 애니메이션이 진행되므로, 스크롤 위치를 계산하는 자바스크립트가 필요 없습니다.

```css
@supports (animation-timeline: view()) {
  .ruled > *, .reveal {
    animation: rise-in linear both;
    animation-timeline: view();
    animation-range: entry 0% entry 70%;
  }
}
```

모든 브라우저가 지원하는 기능은 아니어서 `@supports`로 감쌌습니다. 지원하지 않으면 애니메이션 없이 내용이 바로 보입니다. 투명한 상태를 기본값으로 두지 않고 `@keyframes`의 시작 장면에만 적었기 때문에, 효과가 빠져도 글이 숨지 않습니다.

## 배운 점

첫째, 애니메이션은 모양만이 아니라 겹침 순서도 바꿀 수 있습니다. 가상 요소를 뒤로 보내는 디자인이라면 어느 상자를 움직일지부터 정해야 합니다.

둘째, 움직임은 없어도 되는 층으로 만드는 편이 안전합니다. 설정이나 브라우저 때문에 효과가 빠져도 읽는 데에는 지장이 없어야 합니다.

셋째, 모션 줄이기 대응은 한 번 더 점검할 거리가 남았습니다. 지금 코드에서는 이 설정을 켜도 키보드로 메뉴나 버튼에 초점을 옮기면 위치가 2px 바로 바뀝니다. 미끄러지는 과정은 없지만, 마우스를 올렸을 때처럼 위치까지 고정할지는 더 다듬어 보려고 합니다.
