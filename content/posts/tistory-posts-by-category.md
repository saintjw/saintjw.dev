이 사이트의 블로그 페이지는 원래 티스토리 RSS에서 최근 글 10개를 가져와 최신순으로 보여주기만 했습니다. 글이 600편을 넘기면서 "주제별로 보고 싶다"는 생각이 들었고, 블로그 페이지를 카테고리별 묶음으로 바꿨습니다. 생각보다 간단하지 않았던 과정을 기록해 둡니다.

## 출발점: RSS에는 최근 50편뿐

티스토리 RSS(`/rss`)에는 글마다 카테고리가 들어 있어서, 처음에는 RSS만 묶으면 끝날 줄 알았습니다. 그런데 RSS에 담기는 글은 **최근 50편**이 전부였습니다. 카테고리 여섯 개에 8~9편씩 나뉘어 있었고, 글이 1편뿐인 카테고리 두 개는 아예 보이지 않았습니다.

카테고리마다 전체 글 수와 대표 글을 보여주려면 다른 출처가 필요했습니다.

## 함정 1: 카테고리 주소가 404

카테고리 페이지 주소를 `/category/데스크케어`처럼 만들어 요청했더니 모두 404가 났습니다. 블로그 첫 화면의 링크를 직접 뽑아 보고서야 이유를 알았습니다. 카테고리 이름 양옆에 붙인 장식 `::`까지가 실제 이름이었습니다.

```
/category/::데스크케어::   ← 실제 주소 (URL 인코딩 전)
```

그래서 주소를 직접 만들지 않고, 블로그 첫 화면의 카테고리 목록에 있는 링크를 그대로 쓰기로 했습니다. 같은 목록에 `데스크케어 (150)`처럼 글 수도 함께 있어서, 전체 글 수도 여기서 얻었습니다.

## 카테고리 페이지 속 JSON-LD

카테고리별 RSS가 있는지도 찾아봤지만 없었습니다. 남은 방법은 카테고리 페이지 HTML을 읽는 것인데, 블로그 스킨마다 구조가 달라서 HTML을 직접 파싱하면 스킨을 바꾸는 순간 깨집니다.

다행히 티스토리는 카테고리 페이지마다 검색엔진용 구조화 데이터를 넣어 둡니다.

```html
<script type="application/ld+json">
{"@type":"BreadcrumbList","itemListElement":[
  {"position":0,"item":{"@id":"https://…/614","name":"글 제목"}}, …
]}
</script>
```

여기에 해당 카테고리의 최신 글 6편이 제목과 주소로 들어 있습니다. 스킨이 아니라 티스토리가 생성하는 데이터라 훨씬 안정적이고, 6편이라는 숫자도 카테고리별 미리보기로 딱 좋았습니다. 날짜는 들어 있지 않아서, RSS에 있는 글이면 RSS 날짜를 붙이고 없으면 비워 두었습니다.

## 함정 2: `&middot;`가 그대로 보이는 제목

"당근·번개장터"라는 제목이 화면에 `당근&middot;번개장터`로 나왔습니다. RSS 안에서 `&amp;middot;`로 **두 번 인코딩**되어 있었기 때문입니다. 기존 코드는 `&amp;`를 한 번만 풀었고, `&middot;` 같은 이름 있는 엔티티는 아예 처리하지 않았습니다.

엔티티 표를 조금 넓히고, 더 바뀌는 게 없을 때까지 디코딩을 반복하도록 고쳤습니다.

## 함정 3: 하루씩 밀린 날짜

일요일에 올린 글이 토요일 날짜로 표시됐습니다. 날짜를 `toISOString()`으로 잘라 썼는데, 이 함수는 **UTC 기준**이라 한국시간 오전에 쓴 글은 전날로 계산됩니다. 한국시간을 지정해서 날짜를 만들도록 바꿨습니다.

```ts
date.toLocaleDateString("sv-SE", { timeZone: "Asia/Seoul" }); // "2026-11-08"
```

`sv-SE` 로캘은 날짜를 `YYYY-MM-DD` 형식으로 출력해서 이런 용도로 자주 씁니다.

## 정리

- 공식 API가 없어도 **검색엔진을 위해 공개된 데이터**(RSS, JSON-LD)는 비교적 안정적인 출처가 됩니다.
- 남의 HTML을 읽을 때는 화면에 보이는 구조보다 기계가 읽으라고 넣어 둔 데이터를 먼저 찾아볼 만합니다.
- 페이지는 한 시간마다 다시 만들어지게 해서, 새 글을 올리면 따로 손대지 않아도 반영됩니다.
